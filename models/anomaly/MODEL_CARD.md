# Model Card: AI Behavioral Anomaly Detector (Detector #8)

## 1. Overview
- **Model Architecture**: `IsolationForest` (scikit-learn ensemble)
- **Model Version**: `isolation-forest-v1`
- **Detector Name**: `ai_behavioral_anomaly`
- **Threat Class Emitted**: `anomalous_behavior`
- **Pipeline Artifact**: `models/anomaly/anomaly_pipeline.joblib`
- **Feature Schema**: `models/anomaly/feature_schema.json`

---

## 2. Model Purpose & Role
- **Purpose**: Unsupervised behavioral anomaly detection over Zeek-derived flow telemetry (`conn.log`).
- **Primary Role**: Complements the 7 specialist/deterministic detectors (DDoS, Reconnaissance, DGA, DNS Tunnelling, C2 Beaconing, TLS Anomaly, Exfiltration).
- **Core Question Answered**: *"Does this connection's behavioral kinematics deviate significantly from the learned benign operational baseline?"*
- **Distinction**: The model does **NOT** prove malware or intent; it provides an early warning behavioral outlier signal.

---

## 3. Training & Validation Methodology
- **Training Baseline**: Exclusively trained on frozen benign operational captures:
  - `BENIGN-002` (iperf3 TCP baseline)
  - `BENIGN-003` (iperf3 UDP baseline)
  - `BENIGN-004` (short-duration TCP flows)
  - `BENIGN-005` (normal enterprise DNS queries)
  - `ENC-001` (TLS baseline sessions)
- **Attack Contamination**: 0% (frozen benign baseline kept strictly uncontaminated).
- **Splitting Strategy**: Experiment-level splitting across distinct captures to prevent intra-capture data leakage.
- **Hyperparameters**:
  - `n_estimators`: 300
  - `contamination`: "auto"
  - `random_state`: 42 (fully reproducible)
  - `n_jobs`: -1

---

## 4. Input Features (Shared Feature Layer)
The model consumes 16 canonical features generated by `features/flow_stats.extract_flow_features()`:
- **Numerical Features (14)**:
  - `duration`: Connection duration in seconds
  - `orig_bytes`, `resp_bytes`: Payload bytes sent by originator and responder
  - `orig_pkts`, `resp_pkts`: Packet counts per direction
  - `orig_ip_bytes`, `resp_ip_bytes`: Total IP-layer bytes
  - `total_bytes`, `total_pkts`: Cumulative volume metrics
  - `byte_rate`, `packet_rate`: Kinematic flow rates
  - `byte_ratio`, `packet_ratio`: Directional asymmetry ratios
  - `missed_bytes`: Sequence gap counts
- **Categorical Features (2)**:
  - `proto`: Transport protocol (`tcp`, `udp`, `icmp`)
  - `conn_state`: Connection state (`SF`, `S0`, `REJ`, `RSTO`, etc.)
- **Excluded Features (Leakage Prevention)**:
  - No IP addresses (`src_ip`, `dst_ip`), UIDs, timestamps, ports, or dataset labels.

---

## 5. Output, Scoring & Confidence Semantics
- **Raw Anomaly Score**:
  $$\text{raw\_anomaly\_score} = -\text{decision\_function}(X)$$
  *(Higher values indicate greater deviation from the benign distribution)*
- **Confidence Calibration Bridge**:
  Alert `confidence` is normalized relative to the observed benign baseline range:
  $$\text{confidence} = \max\left(0.0, \min\left(1.0, \frac{\text{raw\_score} - \text{benign\_min}}{\text{benign\_max} - \text{benign\_min}}\right)\right)$$
- **CRITICAL SEMANTICS**:
  - `confidence` is a normalized behavioral deviation score in $[0.0, 1.0]$.
  - `confidence` is **NOT** a calibrated probability of malicious intent.
  - An anomaly confidence of `0.85` means the flow is in the 85th percentile of behavioral deviation from benign traffic, **not** that there is an 85% probability of malware.

---

## 6. Operational Constraints & Limitations
- **Payload Inspection**: None (strictly operates on transport-layer flow kinematics).
- **TLS Decryption**: Not required or performed.
- **Severity Ownership**: Initial detector confidence is passed to `fusion/engine.py`, which deterministically determines operational severity based on asset criticality and multi-threat correlation.
